# CLAUDE TEAM SIX (CT6)

> Internal plugin slug: `architect-team` (preserved for backward compatibility with existing installations + the 26 slash commands). CLAUDE TEAM SIX is the user-facing display name introduced in v2.2.0.

## What this repo is

This repo IS the source of the **CLAUDE TEAM SIX** Claude Code plugin (internal slug `architect-team`) — a spec-to-production multi-agent coding pipeline. It orchestrates **MemPalace wake-up → Phase −2 (Triage) → Phase −1 → 8** against a requirements folder or a plain-language requirement, with sibling pipelines for **bug-fix** (`/architect-team:bug-fix`), **UX testing** (`/architect-team:ux-test`), **mini** (`/architect-team:mini`), **data-engineering** (`/architect-team:data-eng`), and **Playwright-suite building** (`/architect-team:playwright-suite`, v3.65.0).

Current shape (v3.66.0): **56 skills, 39 named agents, 26 slash commands, 7 hook enforcement scripts, 24 Layer-3 verification tools** (counts disk-anchored; `check_separation` 26). Suite **8275 passing + 6 skipped, 0 failed** across 262 top-level test files (win32; the win32/darwin skip-profile difference is real — a darwin host without PyYAML reports 16 skips) — **RECORDED, not asserted**: `docs/measurements/` carries the frozen-tree bracket, and a release run cannot end its turn with an unbacked count (the v3.61.0 `_audit_release_backing` arm). Python is 3.10+ **stdlib-only** throughout; green under both Windows cp1252 and `PYTHONUTF8=1`.

The capability stack in one breath: the executed-diagnosis gate + verification planning + the no-self-imposed-limits rule (v3.66.0 — a root cause is a hypothesis until it survives an EXECUTED falsification: the 24th Layer-3 tool `verify-diagnosis-falsified` + the `_audit_diagnosis_falsified` Stop arm hold a diagnostic-research SR's run open until the leading hypothesis has run its test and a competitor was refuted; `verification-planning` makes "where to verify" an enumerate-and-choose decision with a recorded plan, and a `cannot-verify-without-deploy` verdict without one is a measured gap; ETHOS principle 8 *Understand before acting* is compiled into all 39 agents — no self-imposed turn count, budget, cycle cap, or time box, the ONLY limits are the ones the user explicitly states), the intuition-map lifecycle + the durable Playwright-suite registry (v3.65.0 — `intuition-map-lifecycle`'s ensure/grow/bug-path-upsert verbs make `INTERACTION_INTUITION_MAP.md` a guaranteed, growing, debugging-fed asset every lane consults, and `playwright-suite-builder` + `/architect-team:playwright-suite` build a persona-grouped suite with a committed `suite-manifest.json`, whole-suite enumeration at full integration, and default-deny dev/prod safety — the 7th pipeline-driving skill), the conditional-dependency tier + project-trait arming (v3.63.0 — `CONDITIONAL_PLUGINS` beside `REQUIRED_PLUGINS` and provably disjoint from it, so an optional plugin is reported and remediated but can never gate setup; armed per-project by a recursive marker detector, silently on a deterministic trait and after exactly one confirmation on stated intent; Bauplan is its first consumer), the turn-boundary completion lock (v3.56.0 — a Stop-hook arm in EVERY session whose stopping condition is READ FROM DISK: the harness task list, the transcript-derived ask-ledger, the turn-output rule; only HUMAN kill-switches release it, since v3.61.0 `TaskUpdate(status="deleted")` no longer does, and since v3.64.0 it knows abandonment — open tasks untouched past the staleness window surface as non-blocking inherited debt, the operator `open_work.py retire` verb closes a dead list, and the marker heartbeat is scoped to engaged sessions so dead runs can actually age out), the unregistered-run arm + bracketed suite-measurement engine (v3.60.0), the frontend-E2E loop-exit gate (v3.55.0), the data-engineering lane + knowledge server + data-dictionary/annotations/SQL-mining/JSON-LD engines (v3.49.0–v3.54.0), contract-first parallelism (v3.48.0), evidence-integrity enforcement + the declared-gates registry (v3.47.0), the external-LLM gateway with selectable secondary provider + credit-failover-to-login (v3.58.0), the delivery-adversarial Opus model split (v3.43.0), the agent-immutable deploy opt-in (v3.44.0), the instruction-surface layer with ETHOS compiled into every agent (v3.42.0), and the `services/` tier (Librarian installable; ## Conventions at a glance

- Author commits with explicit override (repo's local git config has a "Paul Ingrram" typo):
  `git -c user.name="Paul Ingram" -c user.email="paulingram@users.noreply.github.com" commit ...`
- Run the test suite via `python -m pytest -v` from repo root (green under both Windows cp1252 and `PYTHONUTF8=1`; the expected pass/skip count for the current release is in the CHANGELOG entry).
- Bump version: update `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json` + `CHANGELOG.md`.
- **Release order is a constraint, not a preference (v3.60.0; sharpened v3.61.0).** Reconcile version + CHANGELOG **first**, **archive the OpenSpec change second** (the `git mv` changes the tree, so archiving after measuring stales the artifact — measured, v3.61.0), commit until the tree is clean, **then** `python scripts/measure/suite_measurement.py --label v<version>` as the LAST act, then commit the artifact (committing it is invisible to the digest by design). Measuring earlier records a `provisional` artifact that backs nothing. Close with `python scripts/docs_tooling/changelog_check.py --require-measurements` — exit 0 or the release is not backed. **This repo has no CI and no pre-commit hook, so that command is the ONLY place the existence arm bites; it is checklist-strength, not gate-strength, and it is on the releaser to run it.**
- Runtime state lives under `.architect-team/` (gitignored). v1.1.0 splits it into **shared** (in main worktree: `locks/`, `run-history/`) and **per-run** (in current worktree: `reviews/`, `teammates/`, `handoffs/`, this-run's `openspec/changes/<slug>/`); the MemPalace itself lives at the workspace root `.mempalace/palace`, NOT under `.architect-team/`. The `scripts/setup/worktree_paths.py` helper resolves both via `shared_state_dir()` / `run_state_dir()`. **v1.2.0** auto-creates the run worktree (default; `--no-worktree` opts out) via `scripts/setup/worktree_lifecycle.py::create_run_worktree(slug)` — branch `architect-team/<slug>`, path `<parent-of-repo>/<repo-name>-<slug>/`. **v1.3.0** auto-cleans merged worktrees on the next run via `cleanup_merged_worktrees()` (with `exclude_current=True` keeping the cwd safe); the `/architect-team:cleanup-worktrees` command is the on-demand variant. **v3.7.0** auto-merges a clean run's branch `--no-ff` into `main` and prunes it (`--no-auto-merge` opts out; a conflict falls back to a PR, never `--force`).
